# 上游来源与改动清单

本文说明 Storyloom 的来源链条，并逐项列出我们相对上游所做的改动，用于满足 Apache-2.0 关于「保留署名」与「声明修改」的要求。

---

## 一、来源链条

```
OpenFic（桌面端 + 自托管）
   ↓  以 React Native 重写为 Android 应用
OpenFicM（Android 应用，本项目的直接来源）
   ↓  二次开发
Storyloom（本项目）
```

| 层级 | 项目 | 作者 | 许可证 | 说明 |
| --- | --- | --- | --- | --- |
| 上游母体 | [syrizelink/OpenFic](https://github.com/syrizelink/OpenFic) | syrizelink | Apache-2.0 | 桌面端 + 自托管的小说创作工具，产品形态与整套 Agent 体系由它定义 |
| **直接来源** | [tioners/OpenFicM](https://github.com/tioners/OpenFicM) | tioners | Apache-2.0 | 把上述工具用 React Native 重写为原生 Android 应用；**本项目的代码骨架来自它** |
| 本项目 | [Meekoriela/Storyloom](../../) | Meekoriela | Apache-2.0 | 在上者基础上改造并持续维护 |

> 我们**没有直接使用 OpenFic 的源码**。OpenFicM 仓库中保留的 `backend` / `frontend` / `desktop` 三个目录才是 OpenFic 的桌面端源码，而本仓库未包含它们（移动端运行不需要）。但 OpenFic 的产品设计与 Agent 体系经由 OpenFicM 间接影响本项目，故在此一并致谢。

## 二、改动清单（第一批：v0.1.0）

### 2.1 供应商高级设置

**背景**：上游仅支持三种接口协议（`openai-compatible` / `google-genai` / `anthropic`），且请求头与鉴权方式写死，国内中转站与自建网关常因此无法接入。

| 文件 | 改动 |
| --- | --- |
| `mobile-rn/src/llm/provider-advanced.ts` | **新增**。定义高级设置的字段、默认值、序列化与解析 |
| `mobile-rn/src/llm/client.ts` | 请求时注入自定义请求头，支持自定义鉴权头名与前缀、可选关闭 tools、可选替换 `max_tokens` 参数名 |
| `mobile-rn/src/llm/model-catalog.ts` | 拉取模型列表时同样注入自定义请求头 |
| `mobile-rn/src/screens/settings-screen.tsx` | 新增「高级设置」折叠区，供中转站与自建网关填写 |
| `mobile-rn/src/components/ui.tsx` | `Field` 组件支持底部说明文字 |

**设计取舍**：配置**未新增数据库列**，而是存放在现成的键值设置表中（键为 `provider.advanced.<providerId>`），避免数据迁移风险；解析器对异常数据一律回落默认值。

### 2.2 品牌与包名独立

| 项 | 原值 | 现值 |
| --- | --- | --- |
| 应用显示名 | OpenFicM | **Storyloom** |
| applicationId / namespace | `com.openfic.mobile` | **`com.meeko529.storyloom`** |
| 应用内更新检查 | `tioners/OpenFicM` | **`Meekoriela/Storyloom`** |

涉及文件：

- `mobile-rn/app.json`（名称、包名、版本）
- `mobile-rn/android/app/build.gradle`（`namespace`、`applicationId`、签名变量名）
- `mobile-rn/android/app/src/main/res/values/strings.xml`（应用名）
- `mobile-rn/android/app/src/main/java/com/meeko529/storyloom/`（原生入口 Kotlin 文件的**包路径迁移**，原路径为 `com/openfic/mobile/`）
- `mobile-rn/src/settings/app-update.ts`（更新检查目标仓库）
- 界面与提示词中的品牌名：`src/agent/runtime.ts`、`src/lib/export.ts`、`src/screens/assistant-screen.tsx`、`src/screens/projects-screen.tsx`、`src/screens/settings-category-screen.tsx`、`src/settings/config.ts`、`src/settings/oh-story-updater.ts`

**效果**：包名与官方版不同，**两者可以共存**，安装本项目无需卸载官方应用。

## 三、改动清单（第二批：v0.1.x）

### 3.1 首次启动零下载

**背景**：上游要求 5 项运行资源全部就绪才允许进入应用，其中含 219 MB 的重排模型（占总量 93%），且资源托管于国内不易访问的地址——下载失败时**页面没有出口**，用户被永久挡在启动页。

| 文件 | 改动 |
| --- | --- |
| `mobile-rn/assets/builtin/openficm-agent-catalog.json` | **新增**。基础 Agent / Skill 内容包（478 KB，16 个技能 + 8 个智能体），SHA-256 与上游固定提交一致 |
| `mobile-rn/tsconfig.json` | 开启 `resolveJsonModule`，以支持内容包导入 |
| `mobile-rn/src/settings/remote-resources.ts` | 内容包改为「本地优先 → 回落内置并落库」；资源判定拆分为**必需 / 可选**；本地模型下载增加国内镜像备用源与多源重试；新增 `installOptionalResources()` 支持按项下载 |
| `mobile-rn/App.tsx` | 启动门禁重写：删除硬阻塞逻辑，仅必需资源缺失时提示且**提供「跳过并进入应用」**；本地模型改为后台静默预热 |
| `mobile-rn/src/screens/settings-category-screen.tsx` | 「高级」分类改为可选内容卡片列表，逐项显示用途、大小、状态与单独下载入口 |

**效果**：首次启动所需下载量从约 235 MB 降为 **0**。

### 3.2 编辑器设置

### 3.3 常用服务商一键填充

| 文件 | 改动 |
| --- | --- |
| `mobile-rn/src/screens/settings-screen.tsx` | 新增服务商预设（智谱 / DeepSeek / 通义千问 / 硅基流动 / Kimi / 自定义），点击自动填入类型、名称与接口地址；为各输入框补充说明文字 |

### 3.4 设置页缺陷修复

均在 `mobile-rn/src/screens/settings-category-screen.tsx`：

- 「作者文风」由无效空壳页改为直接打开文风书库
- 规则 / 技能 / 智能体删除增加二次确认
- 修复索引数字输入框「清空后立即被默认值覆盖、无法重新输入」
- 修复重建索引按钮与保存状态串台
- 保存失败时输入框回滚为数据库中的真实值
- 工具权限由「点击循环切换」改为三按钮直选，并支持批量设定
- 规则 / 技能 / 智能体支持编辑（原先只能删除后重新录入）
- 通用 / 连接 / 上下文 / 索引四类支持恢复默认值
- 增加保存成功提示、索引参数变更需重建提示
- 索引参数标签由专业术语改为可读表述

### 3.5 应用图标

`mobile-rn/assets/` 与 `mobile-rn/android/app/src/main/res/` 下的图标资源整体替换为**羽毛笔**图形（墨绿 `#176B57` 底 + 米白 `#EFEDE4` 图形），共 30 个文件：

- `mipmap-{mdpi,hdpi,xhdpi,xxhdpi,xxxhdpi}/` 下 5 个变体（`ic_launcher`、`ic_launcher_round`、`ic_launcher_foreground`、`ic_launcher_background`、`ic_launcher_monochrome`）
- `drawable-{...}/splashscreen_logo.png`
- `assets/` 下的 `icon.png`、`android-icon-*`、`splash-icon.png`、`favicon.png`

> 说明：上游的构建流程不执行 `expo prebuild`，直接编译仓库内的 `android/` 目录，因此替换图标必须同时替换 `android/app/src/main/res/` 下的文件。

### 3.6 构建与签名

| 文件 | 改动 |
| --- | --- |
| `.github/workflows/build-apk.yml` | 构建产物自动发布到 Releases（便于手机直接下载）；Gradle 缓存路径收窄以修复缓存打包失败；新增「解码签名密钥」步骤；构建时注入四个签名环境变量 |
| `mobile-rn/android/app/build.gradle` | `standalone` 变体由写死的调试签名改为「有正式签名用正式签名」；`signingConfigs.release` 明确 `storeType` 为 PKCS12；签名环境变量统一为 `STORYLOOM_RELEASE_*` |

**背景**：上游的 `standalone` 变体固定使用调试证书签名，而云端构建机上没有签名文件、Gradle 每次都会生成一个**全新的调试证书**——导致各版本签名互不相同（**无法覆盖安装**），且调试证书会被部分手机的安全检测拦截。改为固定签名后，各版本签名一致，可直接覆盖安装。
