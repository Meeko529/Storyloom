# Storyloom ✒️

[中文](README.md) | **English**

> (๑•̀ㅂ•́)و✧ 装在手机里的小说创作 Agent —— 通勤路上也能肝三章

**AI 助手直接住在你手机里**：建大纲、写正文、改稿子、记伏笔，全都在本机完成。
不需要电脑，不需要命令行，装上就能写。

## 为什么是 Storyloom？

- 📱 **整个 Agent 跑在手机里** —— 不是网页套壳，写作引擎、语义检索都在本机运行
- 🔒 **数据只在你手机上** —— 没有账号，没有云端同步，断网也能写；卸载前记得导出 (￣▽￣)
- 🔌 **模型你来挑** —— OpenAI / Gemini / Anthropic 三种协议；智谱、DeepSeek 官方接口能连，中转站、自建网关也接得住
- 🆓 **零门槛开写** —— 接个有免费额度的厂商就能用（智谱 / 硅基流动 / OpenRouter 都行），应用不收费、无订阅
- 🧠 **会记住你的书** —— 本地语义检索跑在手机 CPU 上，写到几百章也能翻回第 3 章埋的伏笔 (・ω<)☆

## 这是什么

Storyloom 是基于 [**OpenFicM**](https://github.com/tioners/OpenFicM)（作者 tioners，Apache-2.0）二次开发的 Android 应用。OpenFicM 把 [OpenFic](https://github.com/syrizelink/OpenFic) 的桌面创作工具用 React Native 重写进了手机——**Agent 运行时跑在手机里，作品数据全部保存在本机**。

Storyloom **站在 OpenFicM 的肩膀上，不是从零重写**：界面、本地数据库、手机端 Agent 运行时、本地语义检索都沿用上游；我们在**模型接入、首次启动体验、编辑器与设置、备份与更新、构建与发布**几层做了改造，并在持续维护。改了什么、为什么改，[下面全部列出](#与上游-openficm-的差异)，不藏着 (｀・ω・´)

> 本项目与上游项目无隶属关系，亦不代表其官方立场。改动清单见 [docs/上游来源与改动清单.md](docs/上游来源与改动清单.md)。

## 功能

**写作**
- 本机书架与作品管理，卷 / 章结构，预览优先编辑（防误触）；右上角「⋯ 菜单」收拢**书架样式（网格 / 列表）**与**本机导入**
- **网格视图按书架形态呈现**：书本立在单层立体架板上（板面受光 + 板底深色内边线），书名与「卷 / 章 / 字数」排在**架板下方**；书封为圆角、带浅色书脊，落在板上有接触投影；无封面的作品自动生成排版式书封（按书名配色 + 书名排版，不是色块）
- 自动保存与后台保存，输入法避让
- 章节 / 卷 / 整本导出为 Markdown、纯文本（TXT）或 **EPUB 电子书**（走系统分享，不申请存储权限）
- **一键备份 / 恢复**：全部数据打包为 zip，可保存到网盘或电脑，换机后整机恢复

**助手与 Agent**
- 会话按作品隔离；可编辑历史发言并重跑
- 工具权限三档（允许 / 每次询问 / 禁止），支持逐项与批量设定；**按操作对象分 6 组并带搜索框**（作品与章节 / 角色 / 世界书 / 笔记 / 文风与检索 / 交互与编排）
- **AI 改动先确认**：写章节 / 笔记 / 设定前先展示改前改后，整组接受或驳回，接受后可撤销
- **资料附件**：可把 txt / md / json / csv 等文本文件与 **Word 文档（.docx）** 加入对话，助手按资料内容作答；也可一键存为本作品的笔记，长期可检索引用
- **对话目录**：管理对话是目录式面板——整宽「新建对话」按钮、每条对话可**重命名**、显示消息条数与所用模型；新建对话会先确认，避免误触
- **吉祥物挂件**：助手输入框角落的小形象，六选一（小猫 / 小狐狸 / 纸鹤 / 柴犬 / 小龙 / 墨滴精灵），颜色跟随主题
- **思考过程可见**：模型返回推理过程时（DeepSeek-R1 系、智谱推理档、Gemini、Claude 扩展思考）以可折叠区块展示
- **上下文占用指示**：标题栏实时显示估算占用百分比，点开可见占用条、参与对话的消息数与字数、超范围与超窗口提示
- 实时执行过程可见，支持子智能体委派
- 单次对话共享 24 次模型请求预算（防打满中转站限流）
- **内置创作预设**：长篇 / 短篇 / 剧本三个智能体 + **23 个内置写作技能**（去 AI 味、对话打磨、大纲搭建、剧本场景写作、广播剧脚本、长篇逻辑体检、氛围与场面描写、金手指与能力体系设计、同人二创、诗歌与歌词等，覆盖长篇 / 短篇 / 剧本 / 互动小说多种体裁），装好即有；自建内容可打包为 JSON 分享与导入

**模型接入**（本项目的重点）
- 三种接口协议：OpenAI 兼容 / Google Gemini / Anthropic
- **免费模型专区**：独立分类页，五款免费模型点选即配——领 Key、粘贴、一键启用
- **常用服务商一键填充**：智谱、DeepSeek、通义千问、硅基流动、Kimi、OpenRouter，点一下自动填好地址
- **供应商高级设置**：自定义请求头、自定义鉴权头名与前缀、关闭 tools、替换 `max_tokens` 参数——用于接通各类中转站与自建网关
- 写作时与对话时的字体、字号分别设置：正文字号 11 ~ 28 可调，黑体 / 宋体 / 楷体三选，带实时预览

**资料与检索**
- 角色库（支持头像图片）、世界书、三级笔记（整书 / 卷 / 章），**笔记与世界书均可导出**（Markdown，按层级组织）
- 全文搜索 + 本地语义检索（中文嵌入 + 重排，跑在手机 CPU，不联网）
- 双文风系统：参考文风（从导入的 TXT / Markdown / EPUB / Word 文档蒸馏，**文件名取不到扩展名时按 MIME 与文件内容识别**，可跨作品）+ 作者文风（从改稿差异学习）

**设置与应用维护**
- 14 个设置入口按职能分组：基础 / 连接与模型 / 创作系统 / 知识（含「可选内容」）/ 系统；各入口的说明写在对应二级页顶部
- 规则、技能、智能体均可增删改、**按类分组**（技能 6 类 / 智能体 2 组 / 权限 6 组）并带搜索框；**点开技能可看完整指令全文**，内置技能可「复制为我的技能」后再改；索引参数支持恢复默认
- 可选内容按需下载（进阶内容包、本地检索模型），**不装也能正常写作**
- **应用内更新**：在「高级」页检查新版本并直接安装，不用回 GitHub 下载
- **诊断报告一键导出**：含应用版本、设备信息、非敏感设置、**最近错误记录**与**最近操作轨迹**（进过哪些页面、打开过哪本书），反馈问题时附上即可（不含 API Key 与稿件内容）

## 与上游 OpenFicM 的差异

### 1. 首次启动：从「必须下载 235 MB」改为「零下载」

上游要求 5 项运行资源全部就绪才允许进入应用，其中包含 **219 MB 的重排模型**（占总量 93%），而这些文件托管在国内不易访问的地址上——**下载失败时页面没有出口，用户会被永久挡在启动页**。

改动：

- 基础 Agent / Skill 内容包（478 KB，16 个技能 + 8 个智能体）**内置进安装包**，SHA-256 与上游固定提交一致；Storyloom 另内置 23 个自写技能，不改动内容包本身（避免出现校验不一致）
- 资源拆分为**必需 / 可选**：仅内置内容包为必需；Lorn 文风、oh-story 内容包、嵌入模型、重排模型全部改为可选
- 启动页增加「跳过并进入应用」，任何情况下都不会锁死
- 本地模型改为**后台静默预热**，预热失败不阻塞进入
- 模型下载增加国内镜像（hf-mirror）备用源，主源失败自动切换

### 2. 供应商高级设置

上游三种协议可用，但请求头与鉴权方式写死，国内中转站、自建网关（One-API / New-API / 各类反代）常因此接不上。新增五个开关：

| 开关 | 用途 |
| --- | --- |
| 额外请求头 | 每行一条 `名字: 值`，应对 `HTTP-Referer`、`X-Title` 之类要求 |
| 鉴权请求头名字 | 默认 `Authorization`，部分服务用 `api-key` |
| 鉴权前缀 | 默认 `Bearer `，留空即发送原始 Key |
| 不发送 tools | 极少数中转站不支持 function calling |
| 用 `max_completion_tokens` 代替 `max_tokens` | 个别供应商只认前者 |

（实现层面的取舍——为何不新增数据库列、如何回落默认值——见 [docs/上游来源与改动清单.md](docs/上游来源与改动清单.md) 2.1 节，此处不重复。）

### 3. 常用服务商一键填充

供应商表单顶部新增预设按钮（智谱 / DeepSeek / 通义千问 / 硅基流动 / Kimi / OpenRouter / 中转站·自定义），点击即自动填入类型、显示名称与接口地址，用户只需粘贴自己的 API Key。（免费额度说明已统一移至「免费模型」分类页，供应商表单不再重复标注。）

### 4. 编辑器设置独立成页

上游把编辑器相关设置挤在「通用」里。现在独立为「编辑器」分类：字号（11 ~ 28，本次放宽下限）、正文字体三选一（黑体 / 宋体 / 楷体）、带实时预览；设置在返回写作页时立即生效。

### 5. 设置页缺陷修复

共修复 12 处，其中影响较大的四类：

- **误删无法恢复**：规则 / 技能 / 智能体删除增加二次确认，并支持直接编辑（原先只能删除后重新录入）
- **输入被覆盖**：索引数字框清空后不再被默认值立刻覆盖，可重新输入
- **状态串台**：「重建索引」按钮的状态独立，切换其他设置时不再误显示为进行中并禁用
- **显示与实际不一致**：保存失败时输入框回退为数据库中的真实值

完整 12 项逐条记录见 [CHANGELOG.md](CHANGELOG.md) 与 [docs/上游来源与改动清单.md](docs/上游来源与改动清单.md) 3.4 节。

### 6. 图标与品牌

- 应用图标重绘为**羽毛笔**（墨绿底 + 米白图形），含自适应前景/背景/单色与启动画面，共 30 个资源文件
- 显示名：`OpenFicM` → `Storyloom`
- 包名：`com.meekoriela.storyloom`（独立包名，与其他同名应用互不干扰）
- 应用内更新检查指向本仓库：新版本在这里发布，升级提示也指向这里

### 7. 固定签名与自动发布

上游的 `standalone` 构建变体写死使用调试证书，而云端构建机上没有签名文件、Gradle 每次都会临时生成一个**全新的调试证书**——结果是每个版本签名都不同（**无法覆盖安装**），且调试证书会被部分手机的安全检测拦截。

改动：改为使用**固定签名证书**（配置在仓库 Secrets 中），此后各版本签名一致，可以直接覆盖安装。构建产出的 APK 会自动发布到本仓库的 Releases，Release 说明按「新增 / 修复」两节自动生成。

### 8. 应用内更新与诊断报告

- 「高级」页可检查新版本、下载（自动尝试国内加速镜像）并调起系统安装器，无需再去 GitHub 手动下载
- 一键导出诊断报告（应用版本、设备信息、非敏感设置项、**最近错误记录**），通过系统分享发出；**不含 API Key，不含稿件内容**

### 9. 一键备份 / 恢复

- 「高级 → 备份与恢复」：备份包含全部作品、章节、笔记、智能体、技能与设置，打包为 zip 并调起系统分享
- 恢复时选择备份文件、二次确认后覆盖本地数据，重启应用生效
- 不包含 API Key（存于系统安全存储，写入明文文件有泄露风险）与可重新下载的内容包资源

### 10. 设置页分组与内置创作预设

- 14 个设置入口按职能分为五组（基础 / 连接与模型 / 创作系统 / 知识 / 系统），列表只显示名称，说明统一放在各二级页顶部
- 内置长篇 / 短篇 / 剧本三个智能体与 **23 个自写写作技能**（内容自写，不搬外部原文、不译英文原文），与远程内容包按 id 合并、不覆盖上游内容；**内容包的两条读取路径都会合并**这些扩展预设
- **模型页**：当前默认模型大卡 + 供应商列表行（获取模型 / 高级设置 / 删除）+ 模型单选切默认 + 长按模型调整该模型的对话参数（仅此模型或全局）+ 右上角「清理重复」
- **模型能力页**：每个模型集中调整温度 / 最大输出 Token / 工具调用 / 图片输入
- **连接页**：请求超时；各供应商高级设置在「模型」页每行的高级设置按钮里
- **新建供应商三步向导**：供应商 → 高级设置（可跳过）→ 确认

### 11. 写作与助手的持续改造

上游只提供「对话 + 手动搬运」的协作方式：AI 想改稿就直接改，改错了只能自己翻回去。本项目在这条链路上补了三件事——**写入先确认**（确认卡片展示改前改后与红绿增删行统计，整组接受或驳回，接受后提供单级撤销）、**创建类工具**（AI 可直接建作品 / 卷 / 章节，同样先经确认）、**操作轨迹**（进入页面、打开作品等关键动作留痕，闪退后随诊断报告带出，便于定位问题）。

围绕这条主线的配套改造：模型接入侧新增**免费模型专区**（五款免费模型卡片式选用）与**自制内容包**（自建规则 / 技能 / 智能体导出为 JSON 分享）；助手侧把会话管理改为**目录式面板**、资料可作**附件**参与对话、模型推理以**思考过程**折叠区呈现、上下文占用实时可见；书架侧补齐**作品封面与信息**、**笔记与世界书导出**、无封面作品的配色封面卡与网格 / 列表双视图；应用维护侧增加**启动检查更新**与封面 / 头像的**保存即压缩**。

上面这些能力的具体样子见本文「[功能](#功能)」章节，逐文件改动见 [docs/上游来源与改动清单.md](docs/上游来源与改动清单.md)。

## 安装

> 逐步说明、各厂商拦截的详细处理方法、故障排查顺序，见 **[docs/安装与常见问题.md](docs/安装与常见问题.md)**。

### 1. 下载

前往 **[Releases](../../releases/latest)** 页面，下载 `Storyloom-Android.apk` 直接安装（**无需解压**）。

- 要求：Android 9.0 及以上，arm64-v8a
- 签名证书 SHA-256 指纹见 Release 说明，可自行核对

### 2. 如果被手机拦下

国产 ROM 对非应用商店来源的安装包普遍有安全提示，**这是系统行为，不是应用本身的问题**。点界面底部的**继续安装**即可（部分机型需先点「更多」或等倒计时结束）。「应用未备案」「纯净模式」等提示的处理方式，以及各品牌的具体情况，见 **[安装与常见问题 · 四](docs/安装与常见问题.md)**。

### 3. 首次配置模型

应用**不内置任何模型**，需要自备 API Key。最省事的路径是 **设置 → 连接与模型 → 免费模型**：五款免费模型点选即配，领 Key 后一键启用。手动配置（选服务商预设 → 粘贴 Key → 填模型 ID）与 function calling 注意事项见 **[安装与常见问题 · 六](docs/安装与常见问题.md)**。

**首次启动不需要下载任何资源**，装上即可使用；语义检索、文风蒸馏等功能所需的本地模型可在「设置 → 知识 → 可选内容」中按需下载（含本地检索模型、文风技能包与正文字体包）。

## iOS

本仓库不持有 Apple 开发者账号，也不上架 App Store。iOS 上未上架的应用必须通过**侧载（Sideloading）**并自行签名才能安装。

**当前未提供 iOS 安装包。** 仓库内含一个手动触发的 iOS 构建工作流（Actions → Build iOS IPA），产物为未签名的 `.ipa`，尚未在真机验证；Android 版的应用内更新等功能也未适配 iOS。

自行签名的常用工具：

| 工具 | 说明 |
| --- | --- |
| **AltStore**（较常见） | 对新手较友好，支持同一局域网下的电脑完成自动续签 |
| Sideloadly | Windows / macOS 通用，需手动重复签名 |
| 其他签名工具 | 由使用者自行判断与承担风险 |

> 侧载后的安装、续签与失效均取决于你使用的签名方式与 Apple ID 状态，与本项目无关。有任何 iOS 侧载结果，欢迎在 Issues 中反馈。

## 构建

### 云端构建（推荐，本机无需 Android SDK）

推送代码后自动触发；也可在仓库 **Actions** 页手动触发。构建完成后 APK 会自动发布到 **Releases**（说明按「新增 / 修复」两节自动生成），同时保留在当次运行的 Artifacts 中。

### 本地构建

需要 Node.js 22、JDK 17 与 Android SDK；完整的环境要求、命令与提交前自查清单见 [CONTRIBUTING.md](CONTRIBUTING.md)。

### 签名

签名通过四个环境变量提供：

```
STORYLOOM_RELEASE_STORE_FILE        # keystore 路径（PKCS12）
STORYLOOM_RELEASE_STORE_PASSWORD
STORYLOOM_RELEASE_KEY_ALIAS
STORYLOOM_RELEASE_KEY_PASSWORD
```

四项齐全时使用正式签名；缺失时回退为调试签名（仅供本地临时测试）。仓库的构建流水线从 GitHub Secrets 中读取这些值，因此**请妥善保管签名密钥**——丢失后将无法为同一包名发布可覆盖安装的新版本。

## 常见问题

**Q：作品数据保存在哪里？会传到云端吗？怕丢怎么办？**
作品、章节、角色与对话记录都保存在应用私有目录的本地数据库中，API Key 存放在系统安全存储——**只有调用你配置的模型接口时才会联网**，没有其他网络出口。用「设置 → 高级 → 备份与恢复」导出备份 zip 存到网盘或电脑，换手机后选同一份文件恢复即可；卸载应用会清除全部本机数据，**卸载前先备份** (￣▽￣)。详见 [安装与常见问题 · 七](docs/安装与常见问题.md)。

**Q：手机里已经没有旧版，安装仍失败？**
先确认下载是否完整（对比 Release 上的文件大小），再按上面的安装章节逐条排查。若仍无法安装，请在 Issues 中附上手机型号、系统版本与完整提示文字，最好附上「高级」页导出的诊断报告。

**Q：支持 iOS / iPad 吗？**
代码基于 React Native，具备跨平台基础，但当前仅构建 Android 版本；侧载方式见上文 [iOS](#ios) 章节。
